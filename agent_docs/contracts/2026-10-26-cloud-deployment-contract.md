# devsin2 云端通知部署契约

> 初次部署阶段记录。当前调度及现金分配以[每日一次检查与闲置现金预算契约](2026-10-26-daily-cash-review-contract.md)为准；现有挂单按实时状态判断。

用户已明确授权安装 Codex、准备 Python、接通 IBKR 和企业微信、启动定时任务并完成验收。沿用既有策略契约，不提交真实订单、不创建新交易指令、不撤旧单。

## 行为

- 独立根目录 `/home/ubuntu/apps/qqq-tqqq-strategy`；独立 Codex 状态、虚拟环境、配置、日志和账本，不能覆盖其他项目。
- 操作系统定时触发云端 Codex CLI；仅允许读取 IBKR 账户、持仓、订单、成交和行情。Python 复用 `trading_system.strategy` 计算，AI 不得改写参数或输出数字。
- 使用 XNYS 日历：交易日开盘后 5 分钟、收盘后 20 分钟；夏令时和提前收市按日历处理。重启补触发只能产生过期说明，不补下单。
- 企业微信仅发送本策略的每日结果、运行异常和部署测试。Webhook 存在仓库外私密文件，禁止打印至日志和报告。
- 报告分离信号日、采集时刻、实际持仓、计划动作与执行阻断。无实时报价不得产生可执行限价。仍保留旧挂单，不创建新指令。
- Codex 账号、IBKR 授权必须通过用户官方登录；缺权限如实显示阻断。联网、安装成功不能代替端到端验收。
- 数据文件有来源和采集时间，严格校验缺失交易日、非正价格、过期数据；未确认资金归属时不计算可下单数量。持仓状态不因通知而变化。
- 单任务锁与持久运行状态防止重复通知；发送结果未知不盲目重发。SQLite 使用一致性备份。

## 场景与断言

| 场景 | 断言 |
|---|---|
| 完整最新日线 | 使用原策略核心得出确定结果 |
| 缺日线、认证过期、读取失败 | 生成明确失败通知，禁止捏造持仓或报价 |
| 周末、节假日、夏令时、半日市 | 根据日历仅在应运行窗口触发 |
| 重复调度、并发 | 同一信号任务不重复推送，外部未知结果可审计 |
| 企业微信 HTTP 成功但业务报错 | 记录失败，不报推送成功 |
| 重启 | 状态和私密配置保留，服务可自动恢复 |

本次无新增对外 HTTP 服务；Apifox 不适用。真实订单成交不在部署验收范围内。
